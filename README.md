# dupescan

**Find the documents that are the same text wearing a different hat.** `dupescan`
normalises text, shingles it into 5-word phrases, computes 64 MinHash values per
document, and uses 16 LSH bands to avoid comparing every pair. Candidates are
verified with an exact Jaccard, so the reported similarity is measured rather
than estimated.

```console
$ python scripts/demo.py
dupescan 0.1.0  20,000 documents  1,307 truth pairs
minhash  P 1.000  R 1.000  F1 1.000  (1,307 pairs, 6922 docs/s)
exact    P 1.000  R 0.601  F1 0.750  (785 pairs, 46736 docs/s)
```

The exact-hash baseline is seven times faster and misses 40% of the duplicates,
because a single edited word changes every shingle that crosses it.

## Why not just hash the text

Exact hashing answers "is this the same string", which is the easy half. Editing
one word in a 110-word document leaves the meaning and almost all of the content
intact, but breaks every 5-word shingle that contains that word. `dupescan`
measures how much content survives, so a copied-and-lightly-edited document is
still a duplicate.

## How it works

| Stage | Implementation |
| --- | --- |
| normalise | lowercase, keep `[a-z0-9']+` |
| shingle | 5-word sliding window, MurmurHash3 |
| sketch | 64 MinHash values from multiply-add permutations mod 2³¹−1 |
| block | 16 bands × 4 rows; any shared band makes a candidate pair |
| verify | exact Jaccard over the shingle sets, keep ≥ 0.85 |

Banding is what makes 20,000 documents tractable: 200 million possible pairs
become a few thousand candidates. The verification step is what keeps the output
honest — MinHash is only allowed to propose, never to report.

## Results

Corpus: 20,000 documents of 70–150 words, 940 duplicate families, 1,307 pairs at
Jaccard ≥ 0.85. One Node process, one thread, Windows 11.

| Method | Precision | Recall | F1 | Pairs | Throughput |
| --- | --- | --- | --- | --- | --- |
| MinHash + LSH | 1.000 | 1.000 | 1.000 | 1,307 | 6,922 docs/s |
| exact hashing | 1.000 | 0.601 | 0.750 | 785 | 46,736 docs/s |

**Read the perfect score with the caveat it deserves.** The corpus is synthetic,
and the answer key is defined by the same 5-shingle Jaccard the detector uses, so
1.000 measures "did LSH recall every pair at the declared threshold", not "does
this understand paraphrases". A document rewritten in different words would not
be found, and the README says so below.

## Quick start

```bash
python scripts/demo.py
```

Or step by step:

```bash
PYTHONPATH=python/src python -m dupescan gen --count 20000 --docs data/docs.jsonl --truth data/truth.json
node --experimental-strip-types scanner/scan.ts --docs data/docs.jsonl --out data/pairs.json
node --experimental-strip-types scanner/scan.ts --docs data/docs.jsonl --out data/exact.json --exact
PYTHONPATH=python/src python -m dupescan eval \
  --truth data/truth.json --pairs data/pairs.json --baseline data/exact.json --out reports
```

Requirements: Node 22.6+ for the scanner, Python 3.11+ for generation and
scoring. There is no build step and no `node_modules`.

## Limits

- **Lexical, not semantic.** Shingles compare words, not meaning. Paraphrases,
  translations, and reordered paragraphs with different wording are invisible.
- **Synthetic answer key.** Families are generated by editing 1% of tokens, and
  pairs that drift below 0.85 are dropped from the key rather than counted as
  misses. Real corpora have fuzzier boundaries.
- **One machine, one process.** No distributed LSH, no disk-backed index. The
  whole signature matrix lives in memory: 20,000 × 64 × 4 bytes ≈ 5 MB.
- **Threshold is a policy.** 0.85 suits "same document, light edit". Lower it and
  precision falls before recall rises, because unrelated documents about the same
  topic share common phrases.
